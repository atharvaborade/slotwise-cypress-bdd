# Slotwise Cypress BDD

A JavaScript quality-engineering project that tests the Slotwise coaching-booking application with **Cypress**, **Cucumber BDD**, reusable commands, fixtures, API checks, screenshots, videos and multiple Cucumber reports.

This repository is the Cypress companion to the separate [Playwright Quality Lab](https://github.com/atharvaborade/playwright-quality-lab). It uses the same product domain so the two automation approaches can be compared honestly.

## What it tests

- New-member registration, validation, sign-in and sign-out
- Coach selection and available appointment times
- Booking, cancellation and released-slot behaviour
- Health, authentication and provider API contracts
- Cookie-based member sessions and protected appointment data

## Framework structure

```text
cypress/
├── common/                 shared selectors and reusable values
├── e2e/
│   ├── features/           Gherkin feature files
│   └── step_definitions/   JavaScript Given/When/Then implementations
├── fixtures/               stable test-data templates
└── support/
    ├── commands.js         reusable UI and API commands
    └── e2e.js              global Cypress hooks and setup
```

`cypress.config.js` connects Cypress to the Cucumber preprocessor and controls browser evidence. `.cypress-cucumber-preprocessorrc.json` loads the shared step-definition directory and produces Cucumber JSON and message reports. `scripts/generate-report.js` converts JSON into a searchable HTML dashboard.

## Local prerequisites

- Node.js 22–24; Node.js 24 is recommended
- npm
- Chrome or Chromium

Install and run everything:

```bash
git clone https://github.com/atharvaborade/slotwise-cypress-bdd.git
cd slotwise-cypress-bdd
npm ci
npm test
```

`npm test` resets the disposable test database, runs every feature and generates the HTML report. Use `npm run report` separately to regenerate HTML from an existing JSON result.

Open Cypress interactively while the application is running in another terminal:

```bash
npm start
```

```bash
npm run cy:open
```

Other useful commands:

```bash
npm run test:headed
npm run check
npm run test:auth
npm run test:booking
npm run clean
```

Generated evidence is written to:

- `cypress/reports/cucumber-json/` — machine-readable Cucumber result
- `cypress/reports/cucumber-messages/` — Cucumber message stream
- `cypress/reports/cucumber-html/` — human-readable HTML dashboard
- `cypress/screenshots/` — automatic failure evidence
- `cypress/videos/` — full spec recordings

## Why `node_modules` is excluded

`node_modules` is generated by `npm ci` from the committed `package-lock.json`. Excluding it keeps the repository small, reviewable and portable while still installing the exact dependency tree on any machine.

## Workflow status

The workflow template is stored as `.github/workflows/cypress-bdd.yml.disabled`. GitHub ignores it, so it cannot start a runner. Rename it to `cypress-bdd.yml` when manual GitHub-hosted execution is wanted. It contains only `workflow_dispatch`, which means it runs after a deliberate click rather than on every push.

## Test design

The feature files describe observable business behaviour. Step files translate those behaviours into Cypress actions. Fixtures provide stable templates, commands hold reusable operations, and the common module centralizes selectors. Each scenario creates a unique account, reducing collisions between repeated or split executions.
